# 设置 / 存储 / 密码 / 导入导出

## 1. 存储分工

| 数据 | 位置 | 说明 |
|---|---|---|
| 全局设置 | `SettingsStore`（preferences） | 显示、连接特性默认值、窗口、输入等 |
| 连接配置 | `ConnectionStore`（preferences） | **稳定 UUID 作 id** + `updatedAt`（供 UI 刷新/作 key） |
| 密码 | `CredentialStore`（**ASSET**） | 按连接 id 存，**只在连接验证成功后写入** |
| 导出文件 | 用户选择位置（`DocumentViewPicker` + `fileIo`） | JSON，**不含密码** |

- **密码绝不落明文、不进日志、不经命令行传递**：原生侧用 `freerdp_settings_set_string` 设
  `FreeRDP_Password` / `FreeRDP_GatewayPassword`。
- preferences 的字符串字段**先 `encodeURIComponent` 再拼接**，否则控制字符会损坏文件。

### 1.1 系统密码保险箱（只做填充，保存走应用自身）

编辑页的用户名 / 密码框同时充当系统的「登录表单」，让系统密码保险箱能填充已保存的账号：

- 用户名框 `type(InputType.USER_NAME)`、密码框 `type(InputType.Password)`，两者**在同一个界面**
  才构成可识别的登录表单（判定口径见官方「输入框类型说明」与「系统可适配的场景」）。
  这是填充的全部条件，其余字段类型不影响。
- **保存不由应用发起，也无法由应用发起**：密码保险箱的保存是系统在页面跳转时自己判定的；
  编辑页在会话窗口打开的同时离开，系统不会弹保存提示，保险箱里也不会留下本应用的记录。
  `autoFillManager.requestAutoSave` 不解决这个问题——它落到的是**智能填充服务**
  （Scenario Fusion Kit）的「保存至历史表单输入」，该服务只对**已完成认证的企业开发者 +
  AGC 申请审批通过**的应用开放，调用一律被系统拒绝（`onFailure`），与是否上架无关。
  **不要为了密码去接它**：「历史表单输入」是明文表单历史，还会随华为账号云空间同步。
- 没有本应用记录时，系统的填充列表会推荐**其他应用/关联账号**——那是系统的跨应用推荐，
  不代表本应用保存过任何东西。
- `enableAutoFill` 绑定到页面状态，**离开编辑页时置 false**：填充只在停留编辑页期间有效，
  取消 / 返回 / 仅保存 / 删除都不会把未验证的密码交给系统去保存。
- 凭据保存仍走应用自身（见 §1、`CredentialStore`）：保险箱未启用、无锁屏密码或用户拒绝填充时，
  只是少一层系统级填充，不影响连接与重连取密码；两个控件退化为普通输入框。
- `InputType.USER_NAME` 无字符限制，`域`、`\`、`@` 等 RDP 用户名写法不受影响。

## 2. 设置模型：全局默认 + 单连接覆盖

- **显示（分辨率/缩放）**：全局可自动（取当前显示器 + 推荐缩放档位
  `100/125/150/175/200/225`）或手动；单连接可关掉「使用全局显示设置」用自己保存的
  `width/height/scalePercent`。连接前用 `SettingsStore.resolveDisplay(conn)` 解析。
  - `分辨率` 是**输出分辨率**（超分辨率后的目标）；超分辨率关闭时它同时就是会话分辨率。
  - `缩放` 是**会话（超分辨率前）桌面**的 DPI 系数。自动档的来源是 `densityPixels × 100`
    并**吸附**到档位（开了超分辨率时见下一条的换算）。
  - 原生只写 `FreeRDP_DesktopScaleFactor`（缩放交给服务端，客户端不做逐像素缩放）。
- **超分辨率**（`srEnabled` + `srRatioPercent`，全局默认，**与「硬件加速」同级**放在设置页；
  单连接用独立的「使用全局超分辨率设置」开关覆盖，默认跟随全局）：开启后
  **会话分辨率 = 分辨率设置 ÷ 倍率**（取偶像素），服务端按它出画，本机 Vulkan 呈现器再用 XEngine
  空域上采样把它还原到输出分辨率——省解码与带宽，边缘比双线性放大更锐。倍率档位
  `SR_RATIO_PRESETS` = `1.25x`/`1.5x`/`1.75x`/`2x`：**平台只给建议区间**（空域 GPU 超分建议
  `[1.2, 1.5]`），接口本身对倍率无硬限制，档位超过 `1.5x` 是拿画质换带宽（文字多的桌面在 `2x` 下
  边缘会发硬），所以倍率选项与开关在**同一栏**里，不另起一段。
  - **默认缩放随之换算**：自动档 = `推荐值 ÷ 倍率` 再吸附到档位（`SettingsStore.defaultScalePercent`）；
    会话桌面小了、显示时又被放大回输出分辨率，系数按同一倍率缩小才能让远端 UI 保持原来的物理大小。
  - **两个前提**：Vulkan 呈现器可用（即「硬件加速」开着）且设备报 `XEG_spatial_upscale`。
    设置页按超分辨率能力**置灰**并显示原因；不满足时按关闭处理。`SettingsStore.resolveSr()` 是唯一的
    解析与兜底点（`superResolutionUsable()` 把能力与开关合起来判），所以会话绝不会谈下一个
    本机放大不回去的分辨率。
  - 单连接可独立配置的理由：同一台机器走局域网可以不开，走 frp 转发时需要省带宽就开。
- **高级连接特性（音频、忽略证书…）**：默认值放全局 `AppSettings`；单连接保存自己的值 +
  `useGlobalAdvanced` 标志（**默认跟随全局**）。连接前用 `SettingsStore.resolveAdvanced(conn)` 解析。
  编辑页关掉「使用全局高级设置」后才用本连接的独立开关；**保存时仍持久化独立值**，便于随时切回。
- **剪贴板恒开**：不提供任何开关（全局或单连接）；原生无条件置 `FreeRDP_RedirectClipboard`。
  工具栏的「复制/粘贴」手动触发，见 [`session-and-input.md`](session-and-input.md) §4。
- **GFX 恒开**：关掉图形管线会让会话完全不可用，故不提供开关；`Connect` 里无条件置
  `FreeRDP_SupportGraphicsPipeline`。
- **硬件加速**（`hardwareAccel`，进程级）：**只选上屏后端**——开 = Vulkan 呈现器，关 = GLES 呈现器
  且整个会话不碰 Vulkan。解码**始终**是 FreeRDP 的 gdi 软解，与本开关无关（见
  [`gfx-engine.md`](gfx-engine.md) §3）。存在这个开关的原因是 Vulkan 支持参差不齐的设备
  （模拟器完全不可用）：关掉它就能在一台"Vulkan 不好用"的机器上照常跑。判据用**呈现判定**
  （不需要 compute，见 [`native-libraries.md`](native-libraries.md) §6）：不支持时设置页置灰并显示原因，
  把已存的值纠正为关；支持时默认开（新装/未改过设置即为开）。dev 回放页也有同一个开关
  （`路线:CPU/硬件加速`），改它等于改这个设置并重启回放——两个后端可以在同一份录像上当场 A/B。
- **帧率上限**（`maxFps`，每连接，默认跟随全局「连接特性」；档位 0/15/20/30/45/60 fps，0 = 不限制）：
  上限作用在**服务端出帧**上，不是丢弃已到的帧——每个 RDPGFX 帧在 **START_FRAME（解码之前）**被闸到它的时隙，
  而服务端等的**帧回执在该帧结束时才写出**（见 [`gfx-engine.md`](gfx-engine.md) §0.4），所以服务端只会发出
  不超过上限的帧，超出的帧**根本不产生解码与带宽开销**。周期 = `max(1/上限, 该帧自身工作 + 往返)`，
  上限只降不升：内容本身到不了上限时它无影响。闸门在 drdynvc 线程上（同线程还承载 RDPEI 等动态通道），
  上限越低，这些消息最坏多等一个帧间隔。它**只作用于 live 会话**，dev 回放有自己的节拍
  （`fast`/`realtime`），不叠加。
- **回到前台自动重连**（`reconnectOnForeground`，进程级，默认关）：会话窗口从后台回到前台时，
  若该会话已被系统断开，则自动重连一次。它**不是保活**——系统对后台应用先冻结网络资源（约 2s）、
  再释放并 abort socket（约 12s），且官方判定终端类会话（SSH/Mosh/SFTP）不属于合法的高优先级后台服务，
  普通三方应用无法用长时任务撑住"网络空载 / 低频心跳"；官方给同类应用的建议架构就是**客户端前台重连**
  （依据与红线见 `background-keepalive-TODO.md`）。因此这里只兜"回来时发现已经断了"，不与后台管控对抗。
  行为与触发条件见 [`session-and-input.md`](session-and-input.md) §1。
- **开发者选项**（`developerMode`，进程级，默认关）：dev/实验功能的**总开关**。关着时以下入口都不存在：
  首页的「回放测试」；设置页的「抓取 RFX 码流（测试）」「触屏高刷新率（实验）」
  「工具栏触发停留时间」「工具栏隐藏延迟」；以及会话工具栏的性能遥测（网络 / 本机 / FPS / 带宽 / 音频）。
  关掉它还**一并关闭**已开着的抓取，避免"入口被隐藏、后台还在跑"。导入配置**不读取**这个值（回到关），
  所以导入他人的配置不会意外打开 dev 工具。

## 3. 导入 / 导出（`ConfigTransfer`）

- 导出内容 = 全局设置 + 全部连接；**密码不导出**（在 ASSET 中），UI 必须提示"导入后需重新输入"。
- 导出用**独立的 DTO**（`ExportedConnection`）而不是直接序列化 `SavedConnection`：否则会把继承来的
  `password` / `gatewayPassword` 字段带出去。
- 导入按连接 **`id` 覆盖或新增**，并刷新 `updatedAt`（保证 UI key 变化）。入口在设置页底部。
- **随设备能力的全局值不导入**（`hardwareAccel`、`srEnabled`/`srRatioPercent`）：它们在别的机器上未必成立，
  导入后回到默认。**单连接**的 `useGlobalSr`/`srEnabled`/`srRatioPercent` 随连接一起导出导入，
  这样"局域网连接不开、frp 连接开超分辨率"这类分工能整套搬走。
- 解析导出文件时统一 `JSON.parse(text) as Record<string, Object>` 后逐字段读取（原因见
  [`arkts-conventions.md`](arkts-conventions.md) §2）。

## 4. 生效时机（**改设置前必读**）

- 连接相关设置（分辨率/缩放、超分辨率、连接特性、触屏高刷新率、使用 RDP 光标等）在**连接建立时读取**：
  改动后需要**重开会话**才生效，已打开的会话不受影响。
- 窗口尺寸类设置只在**窗口创建时**生效。
- 「回到前台自动重连」在**每次回到前台时重新读取**（不缓存在会话里），会话进行中改也即时生效。
- 回放/抓取这类 dev 开关在**下一次回放开始时**读取（切换路线会重启回放）。
