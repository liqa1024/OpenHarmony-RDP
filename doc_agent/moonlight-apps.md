# Moonlight 主机与应用（发现 / 运行态 / 唤醒 / 应用管理页）

本文件是 Moonlight 路**主机与应用**的家：主机发现与可达性四态、唤醒（Wake-on-LAN）、应用列表与运行态、
主窗口内的应用管理页，以及「连接 / 恢复 / 切换 / 终止」走法的唯一判定。连接列表行与编辑页见
[`moonlight-connection.md`](moonlight-connection.md)；控制端点与 `/cancel` 参数见
[`moonlight-control.md`](moonlight-control.md)；会话窗口「关闭应用」按钮见
[`moonlight-session.md`](moonlight-session.md)。

## 1. 应用管理页

- 列表行「应用」钮进入**主窗口内的应用管理界面**（不是弹窗，主窗口内容切过去）。
- 列出主机应用、显示是否在运行、可关闭在跑的应用；点应用即"连上并打开会话"
  （已在运行且同一个 → 恢复；否则开启并连）。默认应用可设置。
- 正在运行的应用 tile 的两个动作圆钮按「是否已有会话」切换形态：
  无会话 = 恢复 + 关闭应用；有会话 = 断开连接 + 关闭应用并断开。
- **连接中就地显示加载，两个入口按"应用是否本来就在运行"区分**：
  - 点卡片（应用本来没运行）：卡片整体加载；会话真正建立后才显示「运行中」与动作钮。
  - 点「恢复」（应用本来在运行）：只有该动作钮进入加载；卡片与徽标保持不变。
  实现上「在飞的连接目标 / 是否本是运行」记在页面（`Idle → Connecting` 之前也要先置忙，
  否则加载态会闪一下）；动作钮的「有无会话」形态只认 `Connected` / `Disconnecting`。
- **无会话时按现有逻辑；有会话时同一套动作直接落到会话上**——「连接」即断开后重连，无需二次确认。
- 未运行的应用点击 = 连接；已有应用在跑时 = 切换，因此不置灰。正在运行的应用卡片本身不响应点击，
  动作只走它自己的按钮。连接预检按主机当前运行的应用选择 `/resume` 或 `/launch`；
  会话在跑时切换会先断开当前会话再连新应用。
- **不做右键菜单**：动作只在卡片与页面按钮上。


## 2. 主机与应用运行态（`MoonlightHostState`）

- **"主机在跑哪个应用"由 `services/MoonlightHostState` 单一权威持有**（仿 `SessionManager` 的静态监听器：
  `targetOf` / `powerOf` / `httpsPortOf` / `probingOf` / `subscribe`）。列表页的行状态（恢复 / 运行中 / 终止）与应用页的
  「运行中」徽标都从它派生，两者任何时刻都一致；**会话态本身仍在 `SessionManager`**，不混进来。
- **写入**：`markLaunched(id, appId)` 只由后端 `prepare` 成功后调用（用主机实际启动的 `effectiveAppId`，默认应用
  由此补上）——**不在连接发起时乐观写**，否则一次失败的连接会留下幻影「运行中」；`/cancel` 成功 → `markStopped(id)`
  （会话窗口「关闭应用」、应用页两个关闭动作、列表页「终止」三处共用）。
- **可达性四态（在线 / 未知 / 离线 / 服务未起）**：`powerOf(id)` 给出 `HostPower`。判定**先判 OS 存活、再判服务**
  （顺序是判据的一部分）：本会话尚无结果 = **未知**；`probe` 同时发起 OS 存活探与服务探（`serverinfo`），
  **OS 无应答 = 离线**——ICMP 回显（`connection.queryProbeResult`，**需 API 26**，低于则只用 TCP 端口）与
  TCP `445` / `135` / `3389` **并行**、全无应答才算——此时**不等服务探**（主机静默，等只会白搭一个超时）。
  **OS 有应答**才看服务探：服务答 = **在线**、不等 = **服务未起**（`NoService`：主机开着、Sunshine 没运行；服务探的
  超时是"服务应达窗口"，只在这一支才付）。**不能按失败类型分**（超时 / 立即失败）：Windows 防火墙对未放行的端口
  **丢弃而非拒绝**，"主机开着但 Sunshine 没起"同样表现为超时。
  **不可达时 `targetOf` 一律报 0**（`currentGame` 保留、主机回来即恢复），故恢复 / 终止与「运行中」徽标在离线 / 服务
  未起时都不出现；主机侧动作（终止 / 关闭应用）前先查 `reachableOf`，不可达只提示「主机离线」。同 moonlight-android 的
  `ComputerDetails.State` + `runningGameId`。**判据仍是启发式**：OS 存活探全无应答会误判成离线（ICMP 被拦且这些端口
  被关），故"离线"只表达"连不上"、不硬断"已关机"。
- **行动作按四态**（仅 Moonlight 行；RDP 无探测、恒按在线）：未知 / 服务未起 → 刷新；离线 → 唤醒；
  在线 → 连接 / 运行中 / 终止。右键菜单同步去掉连接类项。**有会话时不受影响**（会话态优先）。
- **唤醒（Wake-on-LAN）**：显式手点、**绝不自动**，且**只对离线态提供**（主机开着时唤醒无意义，服务未起只提示去开
  Sunshine）。**首次点唤醒先弹一次设置引导**（自定义弹窗，正文 + 可点教程链接；确认「知道了」后才发包），
  该引导只弹一次（`AppSettings.wolHelpShown`）。主机 MAC 编魔术包（6×`0xFF` + MAC×16）经 UDP **广播**
  （`255.255.255.255`，端口 `9` / `7`）发出（`services/WakeOnLan`），成功仅代表已发送、**不保证唤醒**；
  **只有已存 mac 才能唤醒**（`supportsWake`），无 mac 时唤醒钮置灰而非隐藏。发包后进入**开机检测**：每 `2s` 探测、
  期间动作位显示**加载**、再点一次只取消检测（不重新发包）。**四种结束，只有一直静默才等满 `120s`**：**在线**（唤醒成功）；
  **服务未起**（主机已开机、Sunshine 没运行——唤醒其实已成功）与**本机网络已离开主机网段**（不可能再唤醒）都**提前结束**；
  `120s` 超时才提示未上线。
- **唤醒可行性只看发送路径**：魔术包是**受限广播、路由器不转发**，只有本机与主机**同网段**才可能送达——离线探测
  （`probe`）顺带按本机链路地址判一次（`services/WakeOnLan`，随 `refresh` 重算）：**判定不同网段（含本机无任何网络）**
  则唤醒钮置灰并说明原因、点按只提示不发包；**判定不了**（有网络但读不出
  链路地址，或主机名解析失败）不置灰。发包时把 UDP **钉到主机所在的那个网络**（`NetHandle.bindSocket`），避免默认路由
  把广播从蜂窝等非局域网接口发出。**网卡是否在 WoL 待机不可探测**——待机网卡与断电网卡同样无 ICMP/TCP/ARP 应答，
  这里只能区分「发不出去」与「能发但主机没回」，**不硬断**「网卡离线」。
- **探测收敛外部变化**：`refresh` 只做 `serverinfo` 轻探测（服务内合并同一连接的重复探测，起止经监听器广播
  `probing` 标志，行据此派生加载态），列表页（`onPageShow`、
  行右键菜单「刷新」）、应用页（`onPageShow`）与会话页进入 `Idle`/`Failed`（弹出重连卡，含主机断连与连接超时）
  时各触发**一次**；应用页的 `probeApps` 也回填 `setProbed`。只有 `/cancel` 这类"动作已发完、主机异步停应用"
  另有短延迟复探（`refreshAfter`）兜底，其余不叠延迟探测；预检失败由 `prepare` 的 `!ok` 分支单探。
  探测成功时顺带回填 `mlMac`（见 [`moonlight-connection.md`](moonlight-connection.md) §2）。**不做周期轮询**——
  手动刷新 / 页面进入即兜底，避免后台常驻探测。

## 3. 连接动作走法（唯一入口与判定）

- **连接动作（连接 / 恢复 / 切换 / 终止 / 断开）只有一个走法入口与一处判定**：
  - 走法统一经预检（`MoonlightConnector.prepare`）选择 `/resume` 或 `/launch`；判定集中在
    `utils/ConnectAction.ets` 的 `connectActionFor`（协议中立），连接行与卡片共用；主连接动作与
    行菜单的协议差异落在连接模型的子类（`RdpConnection` / `MoonlightConnection`，见
    [`architecture.md`](architecture.md) §2）。主页主按钮对 Moonlight 统一为「终止」
    （关闭会话 + 关闭主机应用 = `/cancel` + 断开），**按钮上不出现「恢复」**（恢复在右键菜单）；
    应用页保留「恢复」按钮，其「断开连接」用专用断链图标（`ic_disconnect`）。
  - **「有应用在跑」只看 `hostTargetId`**：`hostTargetId ≠ 0` 即「恢复」（默认应用不同才「切换」），**不要求本连接
    配了默认应用**（`targetId` 只分恢复 / 切换，可为 0）。两界面必须同判——连接行传的是本连接默认应用（可能 0），
    应用页传的是具体 app id（恒 > 0），拿 `targetId > 0` 当门槛就会让连接行把运行中误判成「未运行」。
  - **RDP 不存在恢复态**：会话关闭即完全断开，`hostTargetId` 恒为 0，主按钮保持「断开连接」。
  - 任何触发"打开 / 恢复某应用"的 UI（含任何新增的显式入口）都必须经这个预检；
    **不要在预检之外直接打 `/launch` / `/resume`**。
