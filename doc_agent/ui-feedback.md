# 反馈与提示

反馈层负责把事件或状态变化转换成用户能感知的通道，并把模态、Toast 与生命周期收口到窗口级宿主。
本文描述系统模型、通道选择、优先级、文案、时长、无障碍与代码落点。
视觉取值归 [`ui-visual.md`](ui-visual.md)，组件结构与页面骨架归 [`ui-framework.md`](ui-framework.md)，
协议专属文案与行为归对应协议文档。

## 1. 系统模型

### 1.1 管线

```text
事件 / 状态变化
  → 反馈策略：是否需要用户动作、是否需要阅读、是否有内联落点、结果是否已可见
  → 通道：状态自明 / 内联 / Toast / Notice / Confirm / StateView / StatusCard / Tooltip / 视觉预告 / 加载
  → 反馈宿主：按窗口 / UIContext 隔离
  → 生命周期：排队、去重、展示、处理、释放
```

### 1.2 两个维度

|  | 状态型（随状态存在） | 事件型（一次性） |
|---|---|---|
| 非阻断 | 状态自明、内联、加载 / 进度 | Toast |
| 阻断 | StateView、StatusCard | Confirm、Notice |

- **阻断性**：Confirm / Notice 要求用户处理；StateView / StatusCard 阻断内容或会话；其余不阻断。
- **持续性**：状态型在状态存在期间持续，事件型有明确的开始与结束。

### 1.3 状态反馈与消息反馈

- **状态反馈由状态派生**：状态在就显示，状态消失就消失；不用一次性消息播报。
  `StateView`、`StatusCard`、内联反馈、加载属于此类。
- **消息反馈是一次性事件**：有明确开始和结束；不能用状态卡长期占位。
  Toast、Notice、Confirm 属于此类。
- 状态用 Toast 会丢、会重复；一次性结果用状态卡会长期占位。

### 1.4 作用域与所有权

- **控件**：Tooltip、控件加载态、状态自明；由控件自己负责。
- **页面**：内联反馈、StateView；由页面负责。
- **会话**：StatusCard、会话内 Toast / Notice、视觉预告；由会话页负责。
- **窗口**：模态队列与 Toast 去重；由该窗口的反馈宿主负责。
- **分工**：页面 / 协议负责触发条件与文案；反馈宿主负责排队、展示、关闭与释放；视觉层负责材质与取值。
- **隔离**：宿主按 `UIContext` 隔离，不做进程级全局队列；多个会话窗口的模态与 Toast 互不阻塞。

### 1.5 不变式

- 同一事件的同一层信息只播报一次；状态徽标可以保留，详情不重复。
- 同一窗口同一时刻最多一个模态；后到的模态请求排队，不叠层、不合并。
- 模态打开期间不显示 Toast；关闭完成后再允许。
- 关键错误必须有可停留 / 可确认的通道，不能只靠 Toast。
- 反馈归属发起它的页面 / 窗口；页面或窗口离开时释放宿主，活动与排队模态被取消。
- 选择通道先看“用户是否需要动作”，再看“有没有内联落点”，最后才看“是否短到可以用 Toast”。

## 2. 通道

| 通道 | 语义 | 落点 | 阻断性 |
|---|---|---|---|
| 状态自明 | 操作结果已由控件、列表或页面状态表达 | 开关、选中、徽标、导航、运行态 | 否 |
| 内联反馈 | 与字段、区块或操作绑定的持续信息 | `FormField`、`SettingToggleRow`、`SettingSliderRow`、`ScaleSetting`、`FormSection`、页面结果行、`ClipboardTransferStatus` | 否 |
| 轻提示（Toast） | 一次性、短、无需操作的受理或结果 | `utils/UiUtil.ets` 的 `showToast` → `utils/FeedbackHost.ets` | 否 |
| 通知（Notice） | 需阅读并确认的通知、首次教学、一次性建议、失败详情 | `utils/UiUtil.ets` 的 `showNotice` + `components/PromptDialog.ets` | 是（需确认） |
| 确认（Confirm） | 有后果操作前的决策 | `utils/UiUtil.ets` 的 `showConfirm` + `components/PromptDialog.ets` | 是（需决策） |
| 页面状态 | 整页空、加载、错误 | `components/StateView.ets` | 阻断内容区 |
| 会话状态 | 会话连接、断开、失败 | `components/StatusCard.ets` | 阻断会话 |
| 控件解释 | 控件用途 | `.bindTips` | 否 |
| 视觉预告 | 用进度或几何预告即将发生的界面变化 | `ToolbarRevealHint`、`ToolbarTouchBar`（见 [`session-layer.md`](session-layer.md) §9） | 否 |
| 加载 / 进度 | 操作进行中 | `LoadingProgress`；`ControlDisc`、`FabButton`、`MoonlightAppTile`、`ConnectionRow`；`ClipboardTransferStatus` | 否（禁用触发） |

`PromptDialog` 的外壳、按钮布局与视觉取值见 [`ui-framework.md`](ui-framework.md) §4.1 与
[`ui-visual.md`](ui-visual.md) §8；剪贴板进度、连接失败分类等协议侧文案仍归对应协议文档。

## 3. 选择判据

按以下顺序判断，命中即停止：

1. 需要用户决策或确认后果 → **Confirm**。
2. 需要用户阅读并确认（多行说明、多行教学、一次性建议、失败详情） → **Notice**。
3. 有自然的内联落点（字段、区块、操作结果、进度） → **内联反馈**。
4. 操作正在进行 → **触发控件加载态**；长任务且可取消 → **内联进度**。
5. 整页内容不可用 → **StateView**；整会话被阻断 → **StatusCard**。
6. 本地界面已经给出可见结果 → **不再提示**。
7. 短、一次性、无需操作、界面没有自然落点 → **Toast**。
8. 只是解释控件用途 → **Tooltip**。
9. 只是预告即将发生的界面变化 → **视觉预告**。
10. 以上都不满足 → **不提示**。

### 3.1 场景对照

| 场景 | 通道 |
|---|---|
| 字段为空、格式错误 | 字段内联错误（`FormField.error`）；提交时聚焦第一个错误字段 |
| 跨字段冲突、提交失败、保存失败 | 页面或区块内联错误；错误靠近操作按钮，可重试时保留重试入口 |
| 能力不支持、当前不可用 | 控件置灰 + 可见原因；连接行唤醒禁用时显示行内原因标签 |
| 删除连接、关闭仍有会话的主窗口、取消文件传输 | Confirm |
| 列表发起连接失败 | Notice |
| 应用页发起连接失败 | 应用列表上方的页内错误条；会话窗已开时以 StatusCard 为主反馈 |
| 会话连接、断开、失败 | StatusCard |
| 多行首次教学、一次性建议 | Notice，并记录对应范围的一次性标记 |
| 单行操作结果、后台 / 远端动作受理、剪贴板复制结果 | Toast |
| 本地列表、开关、页面、壁纸、默认应用已变化 | 不提示，避免重复描述结果 |
| 页面首次加载、空列表、加载失败 | `StateView` |
| 导入 / 导出进行中 | 内联加载 + 具体动作文案 |
| 导入 / 导出结果 | 内联结果行，区分成功 / 失败 / 取消 |
| 控件用途、快捷键 | Tooltip，不承载关键状态 |
| 工具栏唤出、触屏手柄 | 视觉预告，不承载必须阅读的信息 |

## 4. 各通道规则

### 4.1 状态自明

- 开关、选中、列表徽标、运行状态、页面跳转、壁纸与默认应用等已经可见的结果，不再补 Toast 或 Notice。
- 结果可见但原因 / 下一步不可见时，补的是原因 / 下一步，不重复结果本身。
- 只有结果是**远端 / 后台完成**、或本地没有自然落点时，才用 Toast 补充“已受理”。
- 唤醒结束：在线用 Toast；服务未起、离网、取消检测由行状态或可见原因表达，不再 Toast。
- 状态不能只靠颜色；徽标、图标或文案必须能独立表达含义（取值见 [`ui-visual.md`](ui-visual.md) §3.3）。

### 4.2 内联反馈

- 字段校验落在 `FormField.error`：错误优先于 `hint`，错误文案短，修正后立即清除。
- 跨字段冲突、提交失败、保存失败才用页面级或区块级错误文本；错误应靠近触发动作，并带可执行的下一步。
- 能力不支持用可见原因说明：`disabledReason` / `noneHint`，或连接行的“缺少主机 MAC / 不在主机局域网”标签。
  置灰控件不再靠 Toast 解释；Tooltip 只作补充。
- 导入 / 导出进行中显示具体动作（“正在导入配置…” / “正在导出配置…”），结果行区分成功 / 失败 / 取消；
  失败用危险色，成功与取消用次级文字，结果保留到下一次操作或离页。
- 传输进度常驻在进度行（`ClipboardTransferStatus`），期间不另发 Toast 描述同一进度。
- 内联错误必须同时有文字，不能只靠颜色或图标。

### 4.3 Toast

- Toast 是系统渲染的静默轻提示，不接收焦点、不阻断操作；应用只提交文案与材质参数。
- 适用：一行、无需操作、无自然内联落点、本地界面尚未表达结果。
- 不适用：关键错误、需要阅读第二遍的内容、需要决策的内容、字段校验、进度播报。
- 一行写完；不写句号、不写“请稍候”、不写裸错误码；约 30 个汉字以内。
- 时长由 `ToastTier` 统一提供：
  - `Short`：`1500ms`，会话内确认、手势提示、剪贴板复制结果；
  - `Default`：`2000ms`，普通一次性结果；
  - `Long`：`2500ms`，单句建议或远端受理结果。
  调用点不传裸毫秒；超过一行或需要阅读时间的内容改 Notice / 内联。
- 同一个 `UIContext` 内，相同文案在 `1s` 内只显示一次；状态轮询只在边沿触发，避免刷屏。
- 模态打开期间不显示 Toast；确认/通知关闭完成后再允许后续提示。
- 反馈归属发起它的页面 / 窗口；页面离开时由宿主释放，不再保留该窗口的 Toast 去重状态。
- 手势 / 操作中的单行情境提示可以按需重复，但同一动作或 `1s` 内去重；它不承担跨会话教学，不需要持久标记。

### 4.4 Notice

- 适用：多行说明、多行首次教学、一次性建议、失败详情、帮助。
- 不适用：纯成功、单行结果、字段校验、已有内联落点或 `StatusCard` 的内容。
- 结构：标题 + 正文 + 一个确认按钮（默认“知道了”）；不提供取消。
- 一次性教学 / 建议的标记范围与触发范围一致：跨会话的用设置持久标记，单次连接 / 单次页面的用页面标记；
  同一触发内不重复。WoL 帮助与触控板建议走跨会话标记，帧率提示走单次连接标记。
- 会话内 Notice 是模态，会阻断远端输入；只在必要且只出现一次时使用。单行、非阻断提示用 Toast。
- 已有 `StatusCard` 承载连接失败详情时，不再用 Notice 重复同一错误。

### 4.5 Confirm

- 只用于有后果、不可逆或需要用户明确选择的操作：删除连接、关闭仍有会话的主窗口、取消文件传输。
- **删除连接必须确认；会话断开、关闭主机应用、终止主机应用不二次确认。** 不可撤销的删除与可恢复的会话动作分开对待。
- 结构：标题写动作或后果，正文写后果；取消在左，确认在右；确认按钮用动词（删除 / 断开 / 取消传输），不用“确定”。
- 危险色只给破坏性动作；确认窗默认保留取消；不自动消失；后到的确认排队，不叠层。
- 确认完成后关闭，再按结果走 Toast / 内联 / `StatusCard`；模态回调里的 Toast 在关闭完成后才允许出现。

### 4.6 StateView 与 StatusCard

- `StateView` 用于整页内容不可用：空、加载、错误；错误态按标题、原因、动作组织，
  结构与取值见 [`ui-framework.md`](ui-framework.md) §2.1 与 [`ui-visual.md`](ui-visual.md) §8。
- 页面级加载如果持续超过一瞬，必须有文字说明正在加载什么；纯转圈只用于触发控件上的短操作。
- `StatusCard` 用于会话级阻断：连接中、断开中、连接失败；同一时刻只显示一个。
- 连接失败详情已在 `StatusCard` 内，不再用 Toast / Notice 重复；失败卡提供“重试 / 返回”等出口。
- 加载态完成时必须被结果态替换，不能留下孤立转圈。

### 4.7 Tooltip

- 只解释控件用途；不承载错误、状态、必须知道的信息或唯一入口。
- 同一个悬停目标只保留一个 Tooltip；父容器与子控件不要同时挂 `bindTips`，否则会叠层。
- 挂 `bindTips` 的宿主必须**自身注册 `onTouch`**：PC 上鼠标左键按下会被转成触摸事件，宿主不在触摸目标里时，
  切页 / 切窗口后 pending 的 `appearingTime` 定时器不随节点收口，会在新页面上弹出残留气泡（位置还偏左漂移）。
  最容易命中的操作是"悬停后不等提示出现就点击"；已经显示出来的气泡不会残留。
  - 宿主有按下反馈时，`onTouch` 与 `onMouse` 写同一份 pressed 状态（不要当成重复实现删掉）；没有按下反馈时
    注册一个空 `onTouch` 即可，它的作用只是让宿主成为触摸目标。样板见 `ControlDisc`、`FabButton`、`MoonlightAppTile`。
  - 已实测无关（按这些方向修过，无效）：子节点设 `hitTestBehavior(HitTestMode.None)`、宿主加 `BLOCK_HIERARCHY`、
    `responseRegion`、`transition`、根节点用 `Row` 还是 `Stack`、调用点是否带通用属性（会生成 `__Common__` 包装层）。
    "让子节点参与命中测试"也不够：没注册触摸处理的子节点即使参与命中，指针压上去仍不是触摸目标。
  - 未解：完全没有 hover / press 状态反馈的宿主（如 `ConnectionRow` 的"编辑"热区）实测未出现残留，机制未定位；
    规则仍统一要求注册 `onTouch`，不要依赖这条未证实的差异。
- 宿主若要成为独立交互单元，再按需加 `HitTestMode.BLOCK_HIERARCHY`（会断开祖先 hover，祖先依赖悬浮时不要加）；
  它只解决祖先误响应，与残留无关。
- 不要用空字符串“关闭” Tooltip：`bindTips('')` 仍会创建空气泡。没有提示时不要挂载该修饰符，
  或用与当前状态一致的非空文案。
- 加载 / 运行态用状态 Tooltip（`处理中…` / `正在连接` / `运行中`），不显示原动作提示；
  禁用或能力限制的原因用可见文本 / 标签，不能只放在 Tooltip。
- 长文本或状态原因不用 Tooltip；改用行内徽标或内联文本。连接行唤醒禁用即用行内标签说明原因。
- Tooltip 不能作为键盘用户唯一的信息来源；关键信息必须有可见文本。

### 4.8 加载与进度

- 本地操作：在触发控件原地显示加载（按钮、行、FAB、磁贴），同时禁用重复触发和聚焦。
- 长任务：用内联进度 + 文案；可取消时提供“取消”，需要持续可见时钉住进度行。
- 页面首次加载用 `StateView` 的加载态；会话连接用 `StatusCard` 的加载态。
- 不用全屏遮罩表示局部操作，不用 Toast 播报“正在…”。
- 操作完成必须结束加载态；结果不可见时再补 Toast / 内联结果。

### 4.9 视觉预告

- 只预告即将发生的界面变化（如全屏工具栏唤出、触屏手柄），不承载必须阅读的信息。
- 必须能被输入穿透、不遮挡画面；同时保留点击 / 手势 / 按钮等非视觉入口。
- 不能用动画或颜色单独表示错误、成功或状态；这些仍按 §4.1 / §4.6 表达。
- 具体行为见 [`session-layer.md`](session-layer.md) §9。

## 5. 优先级、并发与生命周期

- 通道选择优先级从高到低：**Confirm > Notice > StatusCard / StateView > 内联反馈 > Toast > Tooltip / 视觉预告**。
- Confirm、Notice 与自定义内容对话框都是模态；同一个 `UIContext` 同时最多一个模态，后来的请求按 FIFO 排队，不叠层、不合并。
- 模态打开期间不弹 Toast；Tooltip 不覆盖模态。
- 同一事件的同一层信息只播报一次；状态徽标可以保留，但详情不在 Toast 与 Notice / 内联之间重复。
- 队列按窗口 / `UIContext` 隔离，不做进程级全局队列；多个会话窗口各自的反馈互不阻塞。
- 模态归发起它的页面 / 窗口所有；页面离开时关闭并释放，活动与排队模态被取消，不能把模态留到下一个页面。
- 页面离开时同时释放 Toast 去重状态；一次性标记按 §4.4 的范围保存。
- 轮询型事件只在状态边沿触发反馈；同一错误不随每次刷新重复。

## 6. 文案

| 通道 | 规则 |
|---|---|
| Toast | 一行；写结果或受理；无句号；约 30 字内；不写“请稍候”；不写裸错误码 |
| Notice | 标题写主题或结果，短；正文 1–2 句；只给一个动作；确认词默认“知道了” |
| Confirm | 标题写动作或后果；正文写后果；取消在左；确认按钮用动词；危险色只给破坏性动作 |
| 内联错误 | 写“发生了什么 + 怎么办”；字段错误尽量短；不重复标题 |
| 进度 | “正在 + 对象 / 百分比”；可取消时给“取消” |

- 语气直接、事实化；不用感叹号、不用拟人化、不用“错误！”。
- 错误信息保留可执行下一步；原始错误码、英文原因只进日志，不直接给用户。
  协议侧错误 token 由对应协议文档的映射函数转成可读文案（Moonlight 配对错误走 `MoonlightConnector.describeError`）。
- 不写“本机 / 远端 / 当前”等冗词；不用括号补充第二层信息；一条消息只做一件事。
- 本地界面已经可见的结果不重复描述；成功提示不用单独的“成功”二字。
- 协议专属文案（连接失败分类、剪贴板、主机能力等）仍由对应协议文档维护。

## 7. 时长与持久性

| 通道 | 时长 / 持久性 |
|---|---|
| Toast | `ToastTier.Short` / `Default` / `Long` = `1500` / `2000` / `2500ms`；不随调用点任意变化 |
| Notice / Confirm | 直到用户操作；不自动消失 |
| 内联错误 | 到修正、下次提交或成功为止 |
| 内联结果 | 到下一次操作或离页 |
| 加载 / 进度 | 操作期间；完成时必须替换 |
| StateView / StatusCard | 状态持续期间 |
| Tooltip | 悬停 / 聚焦期间，系统默认 |

- Toast 时长不是阅读时间保证；需要读第二遍的内容不得用 Toast。
- 长任务不能只靠转圈；超过一瞬要有文字，超过数秒要有进度或取消出口。

## 8. 无障碍

- 错误不能只靠 Toast；必须有持续可见的 Notice、内联错误、`StateView` 或 `StatusCard`。
- Confirm 默认提供取消路径；破坏性动作使用危险语义，不用强调色伪装成主操作。
- 状态不能只靠颜色；Toast / Notice / 内联文本需要能被辅助技术读取。
- 加载态同时有文字与指示器；遵循“减少动效”设置。
- Tooltip 不是唯一信息通道；键盘 / 焦点用户必须能获得同样的信息。
- 热区、对比度、字号等取值见 [`ui-visual.md`](ui-visual.md) §11。

## 9. 实现落点

- **窗口级宿主**：`utils/FeedbackHost.ets`。按 `UIContext` 注册；负责 Toast 命名档位、相同文案 `1s` 去重、
  单模态 FIFO 队列、模态打开期间抑制 Toast、页面 / 窗口释放。`ToastTier` 定义在该文件。
- **统一入口**：`utils/UiUtil.ets`。`showToast(ui, message, tier)`、`showConfirm`、`showNotice`；
  页面不直接调用 `promptAction` 拼装这三类反馈。
- **对话框生命周期**：`utils/DialogSession.ets` 负责单个自定义对话框的 open / close / dispose；
  `components/PromptDialog.ets` 提供统一外壳。`PairingPrompt`、`HostSearchPrompt`、`WolHelpPrompt` 都通过
  `FeedbackHost` 排队，并复用同一套生命周期。
- **内联与状态件**：字段用 `FormField`；设置项用 `SettingToggleRow` / `SettingSliderRow` 的 `disabledReason`、
  `ScaleSetting.noneHint`、`FormSection.description`；页面结果用页面内联行；传输进度用 `ClipboardTransferStatus`。
- **页面内联的具体落点**：
  - `EditConnectionPage`：主机字段 `FormField.error` + 焦点；连接 / 保存 / 配对失败在操作按钮上方用危险色内联错误；
  - `SettingsPage`：导入 / 导出进行中用具体动作文案，结果行区分成功 / 失败 / 取消；
  - `MoonlightAppsPage`：连接失败显示在应用列表上方；默认应用与壁纸等本地可见结果不补 Toast；
  - `ConnectionRow`：唤醒禁用时显示行内原因标签，动作按钮禁用且不聚焦。
- **页面级 / 会话级状态**：`StateView` 与 `StatusCard`；页面与 `SessionAbility` / `EntryAbility` 在离开或销毁时
  调用 `releaseFeedback`。
- **视觉值**只在 [`ui-visual.md`](ui-visual.md) 与组件 / 资源中维护；本文件不重复颜色、字号、圆角与阴影取值。

## 10. 不采用

- 用 Toast 承载关键错误、需要决策的内容或需要读第二遍的长文案。
- 用 Notice 播报纯成功或单行结果。
- 对可撤销、低风险操作弹确认；对会话断开、关闭主机应用、终止主机应用做二次确认。
- 多个模态叠层；模态打开时再弹 Toast；同一事件同时用 Toast 和内联 / Notice 播报。
- 用全屏加载遮罩表示局部操作；用 Toast 播报“正在…”。
- 字段校验能字段内联却提升为页面级错误或 Toast。
- 每次调用随意指定 Toast 时长；用延长 Toast 解决长文案。
- 用转圈代替状态文字；用颜色或 Tooltip 作为唯一信息通道。
- 挂空的 `bindTips`、同一个悬停目标叠多个 Tooltip、把长状态原因塞进 Tooltip。
- “请稍候”“操作成功”这类没有对象的空话；裸错误码、英文异常、感叹号。
