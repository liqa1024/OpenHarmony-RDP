# 测试与验证

本文负责测试方法、验证流程、用户交接与测试日志；构建/签名/安装见 [`build.md`](build.md)，
回放与参考画面见 [`rdp-gfx.md`](rdp-gfx.md) §5/§6/§7。

## 1. AI 自测原则

本节只适用于 AI 自己执行的测试；用户参与见 §2 的默认流程和 §4。

- 测试目标是给变更提供证据，不是“跑一遍”。按变更选择最小充分测试：
  构建/静态检查能覆盖的，不升级到设备测试；模拟器能覆盖的，不升级到实机。
- 测试必须可判定、可复现：先明确“观察什么、什么算通过”；优先日志、UI tree、控件 id、断言，
  少做频繁 UI 交互和视觉目测。
- 合并检查，减少重复：同一次改动尽量一次跑完相关路径；不要为同一结论反复跑。
- 日志纪律：用 domain/tag 过滤，先清缓冲，避免垃圾日志；关键结论行尽早抓，或在收尾重打。
- 停止条件：同一失败反复出现且没有新证据时，停下汇报，不无限重试；不要用“再跑一次”代替分析。
- 证据与结论：记录测试环境、路径、观察结果、未覆盖项；不要用“build 通过”代替功能/UI 验证。

## 2. 默认流程

先按“谁操作 × 设备”区分：

| 谁操作 | 模拟器 | 实机 |
|---|---|---|
| AI | 默认自测 | 例外 A（§3） |
| 用户 | 用户 UI 验收 | 用户 UI 验收 + 最终实机确认 |

**重 UI/视觉判断需要用户，与设备无关**：模拟器和实机都一样。不要因为模拟器方便，就把重 UI
测试拿给 AI 做。

模拟器：启动用 `devecocli emulator start "<模拟器名>"`；首次启动需用户同意。已有实例在运行而
AI 要用，先告知一次「正在占用此模拟器，不要关」，之后同一会话内可直接使用。AI 自己启动的实例，
不再需要时自行关闭；原本就在运行的实例，AI 不负责关闭；无法确认归属时按原本就在运行处理。
同一时刻只有一个实例占用 5555。

模拟器不是 Vulkan/硬件加速的依据：RDP 上屏只在真机验证；模拟器的 Vulkan 会按标准接口谎报能力，
呈现器会回落 GLES，不要用模拟器结论约束真机行为。

默认流程：

1. AI 自测（默认模拟器；实机例外见 §3），用 hilog/UI tree/断言覆盖已知路径。
2. 收尾：停止日志收集，清掉为自测加的临时日志/探针，恢复日志级别，避免把噪声交给用户。
3. 交接给用户：说明改了什么、可能影响哪里、AI 测了什么/没测什么，给一个最小起点。
   模拟器由 AI 直接安装/启动，用户只负责测；实机由用户自行安装，AI 只需确保最新 `default`
   构建完成，不主动装包（例外 A 的明确授权除外）。
4. 用户自己决定在模拟器还是实机上过一遍 UI；默认不取 hilog，不规定测试深度，不要求全量回归。
5. 用户报问题后，先按现象排查；只有确实需要日志时，才走例外 B（§4），不预先采集、不默认重测。

用户测试是独立探索，不是 AI 测试的验收副本：AI 的测试覆盖已知路径，用户测试用于发现 AI 没注意到的问题。
AI 的测试通过只说明它覆盖的路径通过，不说明没有问题；不因自测通过而否定用户发现，也不要求用户按
AI 的测试清单走。

## 3. 例外 A：AI 直接操作实机

不是常规档位，只在同时满足以下条件时使用：

- **模拟器覆盖不了**：典型是 Vulkan/硬件加速、设备相关行为；
- **必须反复调试**：不是“上实机更方便”，而是模拟器给不出所需证据；
- 已获得用户明确授权，且签名已配置、设备可用；
- 有明确的停止条件（同一失败无新证据、设备/签名异常、影响用户使用等）。

普通 UI/逻辑测试不要以“实机更真实”为由上实机；重 UI/视觉判断归用户（见 §2）。

执行要求：

- UI 交互/识别最小化；能用日志、UI tree、控件断言解决就不点 UI；必须点时才点，不做频繁截图/目测。
- 不做视觉判断；只报告可判定检查的结果。
- 不留下测试残留：恢复应用/设备状态，停止日志收集，清掉临时探针。
- 遇到签名/连接/权限问题，停下告知用户，不反复重试。

## 4. 例外 B：用户操作 + hilog

只在“具体问题需要日志、UI 上看不出来”时使用；不是默认验收步骤。

- 不要预先采集用户测试日志，也不要让日志常驻；不要一上来就 `hdc list targets`。
- 先根据上下文/测试需求判断是否需要实机；不需要就不提实机。
- 需要日志时，先单独告知用户：
  - 为什么需要日志；
  - 需要保持当前设备连接（不要断开/关模拟器）；
  - 要复现什么操作、观察什么现象；
  - 采集哪个 domain/tag、大概多久。
- 用户同意后（或操作完成后），再 `hdc list targets` 确认连接；如果没连上，立刻停下告知用户。
- 采集方式按情况选：用户操作完一次性取；或 AI 先挂起日志，用户操作时实时/回调；或其他方式。
  无论哪种，先说明方式和准备事项。
- 采集完停止并清理，不要求用户反复复现；日志只用于定位问题，不作为“用户测试必须提供”的交付物。

## 5. 日志、观测与 UI 驱动

### 5.1 日志

- 本应用原生日志：domain `0xD001`，tag `HmRdpNative`；`hilog -r` 清缓冲。
- 不要只按 domain 拉全量：`0xD001` 里有很多其他日志。至少加 tag 过滤：
  `hdc -t <serial> shell "hilog -x -D 0xD001 -T HmRdpNative"`（按实际 tag 替换）。
- 需要更窄时加 `-L E`（或 W）或 `-e "<正则>"`；`-x` 是一次性读完退出，不加 `-x` 是阻塞/流式。
- 取完整日志：`hdc shell hilog` 或 `hdc file recv /data/log/hilog`；落盘日志用
  `<DEVECO_HOME>/sdk/default/hms/toolchains/hilogtool.exe` 解析。
- 多设备必须带 `-t <serial>`；取日志前确认目标设备。
- 格式说明符要带 `%{public}`；没有标记的参数会输出 `<private>`。
- 周期性统计行会很快冲掉缓冲区；关键结论行尽早抓，或让代码在收尾重打一次。
- 加日志探针只在确有必要时；定位完删除，不留在被测路径里。

### 5.2 UI 驱动

- 精确坐标：`uitest dumpLayout -p /data/local/tmp/layout.json` + `hdc file recv`，按控件 `bounds`
  算中心点；每次切页面后重新 dump，不要盲点坐标。
- `uitest uiInput click <x> <y>` 注入的是**触摸**事件，不会触发 `onMouse`；鼠标用 `uinput -M`，
  但它相对/累加移动、指针常不可见，精确定位不可靠。
- 会话窗口可缩放，安装后首次进入通常不是全屏；按全屏推算的坐标会落到桌面或别的窗口上，
  症状是“点了没反应”，甚至把应用窗口关掉/切走。
- 截图：`hdc shell snapshot_display -f /data/local/tmp/x.jpeg` + `hdc file recv`；
  模拟器可用 `Emulator -instance <name> -screenshot`。
- UI 驱动的目的是可判定检查，不是视觉判断；能用控件 id/bounds/断言就不目测。

### 5.3 官方工具对照

- **UiTest（`@ohos.UiTest`）**：`Driver`/`ON` 查找控件，`click`/`swipe`/`inputText`，`screenCap`；
  支持窗口、鼠标、手写笔、触控板。适合控件断言与自动操作，不替代视觉判断。
- **模拟器 CLI**：`Emulator -list` / `-stop` / `-instance <name> -uiLayout/-click/-slide/-fill/-screenshot`；
  `-logZip` 收集模拟器日志。启动优先 `devecocli emulator start`。
- **设备侧**：`uitest dumpLayout`、`uitest uiInput click`、`uinput -M`、截图命令见 §5.2。

## 6. 交接、证据与完成标准

AI 交接：

- 改了什么、构建/静态检查结果、可能影响哪里；
- 测了什么（环境/路径）、没测什么；
- 模拟器可由 AI 装好；实机由用户自行安装（确保最新 `default` 构建完成）；
- 最小起点（不是强制清单，用户可自由探索）；
- 已知风险或需要重点看的地方。

例：

> 我改了 X；我测了 A/B；没测 C；你可以从 Y 开始随便过一遍，发现异常告诉我现象和期望即可，
> 不需要按清单走。

用户交接：

- 做了什么、期望什么、实际看到什么；
- 默认给截图，AI 直接看；需要像素级分析时请保存为文件；录屏不是默认，确需时给短片段和关键时间点，AI 抽帧看关键帧；
- 默认不要求日志。

问题处理：

- 用户报的问题先当作真实现象，不因 AI 自测通过而否定；
- 复现不了先对齐步骤、环境、时机等证据，不默认重测；
- 确需日志时走例外 B，先告知再采集。

完成标准：

- AI 只声称自己覆盖的范围；构建门禁通过不等于 UI/功能已验证；
- 默认流程：用户简单过一遍 UI 是补充，不是全量验收；
- 例外 A：只报告可判定检查结果和未覆盖项；
- 例外 B：报告日志分析结论，不要求用户重复测试。
